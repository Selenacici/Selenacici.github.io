核心判断：真正的时间浪费集中在审核通过后的长尾，而不是普通订单的中位体验。P50只从20分钟升到40分钟，但P90从70分钟升到1,450分钟（24.2小时），说明少量积压单把尾部拉得非常长。9月政策同时改变了自动超时流转规则，因此不能只用“超时事件下降”判断质量改善。
  1. 7月：P50 20分钟、P90 70分钟，绝大多数订单在约1.2小时内得到币商结果。
  2. 8月：P50 30分钟、P90 210分钟，长尾扩大到3.5小时。
  3. 9月：P50 40分钟、P90 1,450分钟，10%的订单需要约24小时以上；这是最需要治理的部分。
  4. 政策断点：8月31日更新“200美元以上默认不自动流转”，9月自动超时事件只剩2次，不能与7–8月直接同比。
  5. 分单建议：先在Nigeria、Philippines、Nepal影子运行；其余1–2个Payroll或低量国家保留基础权重，不做淘汰考核。

六、动态分单政策：简单、可解释、可执行

最终分数 = 50% 付款时长 + 25% 自动超时 + 15% 资料错误取消 + 10% 稳定承接量
指标Payroll看到的规则运营计算当前状态
付款时长（50分）同国家内P50与P90越短，得分越高P50 20分 + P90 30分；按国家内分位排名待逐单时间补齐，不扣分
自动超时（25分）接单后尽量不让订单自动转走只比较同政策、同金额带订单；9月需拆≤$200与>$200政策断点后重建基线
资料错误取消（15分）减少因付款资料错误主动取消资料错误取消率，最低者得满分可用
稳定承接量（10分）持续处理订单，不追求单月冲量成功付款单量与金额量封顶计分可用

档位月度分数下月基础权重处理方式

  • 同国家比较：不跨国家硬比，避免支付基础设施差异造成不公平。
  • 小样本不升降：当月可观察结果少于30单，只展示数据，不调整权重。
  • 变动上限：单月权重最多升降30%，防止订单突然集中。
  • 新政策影子期：先运行4周，只展示不生效；确认数据口径后再用于真实分单。
  • 大额保护：9月以后超时指标必须按≤$200与>$200分层。

七、入驻、低等级与淘汰机制

场景建议政策原因
成熟国家入驻保持“达到SS级币商”作为入驻门槛便于理解，且控制基础能力
成熟国家长期低等级/不活跃滚动60天付款<5单或连续30天无付款，先14天预警；剩余容量≥近90日峰值需求的120%时才移除既清理长期无贡献席位，又避免削弱国家供给
新地区/稀缺国家不因未达SS或低活跃自动淘汰；至少保留1–2个备用Payroll，每90天人工复核Saudi Arabia、Egypt等首先解决“有人能付”
质量差但仍有供给价值降权到30–70并辅导，不立即移除退出应同时看质量与国家替代能力
建议的退出判定：“连续两个月D档”只是触发复核，不是自动删除。只有在付款质量持续差、长期无活跃、且国家剩余Payroll容量足够三项同时满足时才移除。

指标解释
P5050%的已完成订单不超过该时长，代表典型订单体验。
P7575%的订单不超过该时长，显示开始变慢的一段。
P9090%的订单不超过该时长；剩余10%更慢，是判断长尾积压的核心。
P9595%的订单不超过该时长，用于识别最严重的极慢订单。
